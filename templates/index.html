SecureLink – Hybrid Cryptography File Transfer

A defense-in-depth secure transfer system combining the bulk throughput of AES-256-GCM authenticated encryption with the mathematical security of RSA-3072 key encapsulation and SHA-256 integrity hashing.

How Hybrid Cryptography Works in SecureLink

Overcoming the asymmetric speed bottleneck while solving symmetric key distribution.

1. File Hashing

Sender uploads a file. The system immediately computes an authoritative SHA-256 fingerprint of the plaintext bytes for post-decryption integrity verification.

SHA-256 Digest
2. AES-256-GCM

A fresh 256-bit symmetric session key and a 96-bit nonce are randomly generated. The file is encrypted using AES-GCM, producing ciphertext and an authenticated 128-bit tag.

Authenticated AEAD
3. RSA-OAEP Wrap

The ephemeral AES session key is encrypted with the recipient's public RSA-3072 key using Optimal Asymmetric Encryption Padding (OAEP). Only the recipient can unlock it.

Asymmetric KEM
4. Decrypt & Verify

Recipient decrypts the AES key with their RSA-3072 private key, decrypts ciphertext, validates the GCM authentication tag, and confirms SHA-256 digest match.

End-to-End Verified
Zero Plaintext Storage

The server never writes unencrypted files to permanent disk storage. Only ciphertext with random nonces and encrypted keys are retained.

Tamper-Proof Guarantee

If an attacker alters even a single bit in the encrypted payload on the server, the AES-GCM GHASH authentication tag instantly fails, blocking decryption.

Strict Authorization

Granular access control policies ensure that users can only view, download, or decrypt transfer records they directly authored or were assigned as the recipient.
